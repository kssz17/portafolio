Principios con los que escribo código

No son trends — son la base con la que construyo software pensado para durar.

01
Código limpio

Nombres claros, funciones cortas y una sola responsabilidad por archivo. Si otra persona no lo lee fácil, lo reescribo.

02
Seguridad

Validación de entradas, control de accesos, datos sensibles protegidos y autenticación sólida. En banca, la seguridad no es opcional.

03
Testing

Pruebas unitarias con JUnit para la lógica crítica y pruebas de integración para los endpoints. Confianza real al desplegar.

04
Documentación

READMEs útiles, comentarios donde el "porqué" no es obvio, y commits con contexto. El equipo siguiente lo agradecerá.

05
Rendimiento

Consultas SQL optimizadas, índices bien pensados y caché donde aporta. Que el sistema responda rápido incluso bajo carga.

06
Arquitectura por capas

Separación clara entre controller, service y repository. Código desacoplado, mantenible y preparado para escalar.

Mi enfoque

El código que escribo
habla por mí.

Prefiero una función que se entienda al primer intento sobre una "ingeniosa" que requiera explicación. Un buen componente debería decir lo que hace antes de leer su implementación.

  • Arquitectura por capas (Controller · Service · Repository)
  • Principios SOLID y código desacoplado
  • APIs REST claras y bien documentadas
  • Tests con JUnit en la lógica crítica
UserService.java 
// Código legible > código "ingenioso"
@Service
public class UserService {

  public String getDisplayName(User user) {
    if (user.getName() == null || user.getName().isBlank())
      return "Usuario sin nombre";
    return user.getName().trim();
  }

  public boolean canEdit(User user, User current) {
    return user.getId().equals(current.getId())
        || current.getRole() == Role.ADMIN;
  }
}
